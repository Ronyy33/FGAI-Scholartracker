# ScholarTrack — Project Report

**Project Sheet PS 6 · Detecting students at risk of falling behind with MLP and LSTM**
Repository: `Ronyy33/FGAI-Scholartracker`, branch `claude/modest-bell-box1op` · Date: 2026-10-16

> All results in this report come from a **synthetic** dataset generated by a documented
> process. They measure how well the models recover that process, **not** how well they would
> work on real students.

## Abstract

ScholarTrack estimates, at the end of each semester, the probability that a student's next
semester will be an academic-difficulty semester (at least one failed subject, or SGPA below
6.0). The probability is shown as an Academic Risk Score from 0 to 100 with a band (Low,
Moderate, High), the main contributing factors and supportive suggestions. No public dataset
matched the college's CSV format with observed future outcomes, so a reproducible synthetic
dataset of 1,200 students (8,561 student-semesters) was generated from the college file's
schema. A majority baseline, logistic regression, a multilayer perceptron (MLP) and an LSTM
over each student's semester sequence were trained with all choices fixed on validation data.
On a held-out test set used once (1,100 student-semesters, 179 students), the three learned
models reached ROC-AUC 0.878–0.881 with overlapping confidence intervals; the pre-registered
rule therefore selected the simplest, logistic regression. Probabilities are well calibrated
(observed difficulty rates of 8 %, 36 % and 76 % in the three bands). The system is delivered
as a FastAPI service and a six-page React dashboard, tested in CI and packaged as a Docker
image.

## 1. Problem and objectives

Colleges usually notice academic difficulty after it has happened: a failed subject or a low
SGPA. The aim is to flag, one semester ahead, students who may benefit from mentoring or
tutoring, while keeping the tool explainable and non-punitive.

Objectives:
1. Define "falling behind" precisely and without leakage (`docs/TARGET_DEFINITION.md`).
2. Build a validated data pipeline from the college's CSV format.
3. Compare a baseline, logistic regression, an MLP and an LSTM honestly.
4. Turn probabilities into a calibrated risk score with understandable explanations.
5. Deliver an API, a dashboard, tests, CI and a deployable container.

## 2. Data

### 2.1 Reference file
The college provided a 200-row CSV (one semester, 66 columns: identifiers, demographics,
attendance and marks per subject). Inspection (`reports/data_quality_report.md`) found
12 impossible values (e.g. attendance 145 %, SGPA 12.4), one unknown elective and two stray
columns; subject credits were recovered exactly by least squares (total 23). The file has no
future outcome, so it cannot be used to *train* a predictor of the next semester. It is kept
locally, read-only, and never committed.

### 2.2 Public datasets
Searches of UCI, OULAD, Kaggle and GitHub (`research/DATASET_RESEARCH.md`) found no public
dataset with the same structure. The closest real benchmark (UCI 697, Portuguese
higher-education dropout) could not be downloaded because the host is blocked by this
environment's network policy; it remains an open extension (Track R).

### 2.3 Synthetic dataset
A generator (`src/scholartrack/synthetic/generator.py`, `configs/synthetic.yaml`) produces six
cohorts in exactly the college CSV format: latent ability and engagement, improving / stable /
declining trajectories, autocorrelated noise, occasional shocks, attrition (4.7 % leave), and
both random and not-at-random missing values. The generator writes **marks only**; labels are
computed afterwards by the same rule used everywhere else. Parameters were tuned on a separate
development seed. Output is byte-reproducible (`reports/synthetic_data_design.md`,
`reports/synthetic_data_profile.md`).

| | Value |
|---|---|
| Students / cohorts | 1,200 / 6 (admission 2019–2024) |
| Student-semesters | 8,561 |
| Labelled rows (next semester observed) | 7,300 |
| Positive rate | 20.5 % |

## 3. Target

Unit: one student at the end of semester *t*. Label 1 if semester *t + 1* contains a failed
subject (total < 40 % or ETE < 40 %) **or** SGPA < 6.0; 0 if all outcomes are known and none
apply; unknown otherwise (never treated as 0). Thresholds are illustrative and configurable
(`configs/target.yaml`) pending the college's official rules.

## 4. Method

### 4.1 Features
Fifteen snapshot features computable from one college-format row (current SGPA,
credit-weighted marks, failures, weakest subject, CIE/ETE/termwork averages, attendance
summaries, previous SGPA and change, study hours, semester) plus three missing-value flags.
Identifiers, gender, age, commute, part-time job and similar fields are excluded on purpose
(`docs/DATA_DICTIONARY.md`). The LSTM receives the same vector for every semester 1…*t*.

### 4.2 Split and preprocessing
70/15/15 by **student** (no student in two partitions), stratified by admission year.
Missing values are imputed with training medians and inputs standardised with training
statistics only; the preprocessor is stored as readable JSON.

### 4.3 Models
| Model | Configuration chosen on validation |
|-------|-----------------------------------|
| Majority baseline | predicts the training positive rate |
| Logistic regression | C = 0.1, no class weighting |
| MLP | one hidden layer of 32 ReLU units, dropout 0.1, AdamW, early stopping |
| LSTM | 1 layer, hidden size 32, dropout 0.3, packed variable-length sequences, gradient clipping |

Selection metric: validation log loss (rewards ranking and honest probabilities).

### 4.4 Calibration, thresholds and pre-registration
Platt scaling vs no calibration was compared by student-grouped cross-validation on validation
data; no model needed recalibration. Each model's flag threshold maximises F1 on validation.
The selection rule (lowest validation log loss; models within 0.005 tied; ties go to the
simpler model) and all thresholds were committed to Git (`776700c`) **before** the test set
was scored once.

### 4.5 Risk score and explanations
Risk score = round(100 × probability); bands Low 0–29, Moderate 30–59, High 60–100 (demo
defaults in `configs/risk_bands.yaml`). Explanations perturb five *concept groups*
(current results, previous semester and trend, attendance, study time, stage) to a typical
student's values and report the change in risk points. Suggestions come from eight
supportive rules in `configs/recommendations.yaml`, triggered by observed indicators, not by
the model.

## 5. Results (test set, used once)

| Model | ROC-AUC [95 % CI] | PR-AUC [95 % CI] | Brier | F1 | Top-10 % capture |
|-------|-------------------|------------------|------:|---:|-----------------:|
| Majority | 0.500 | 0.204 | 0.1622 | 0.338 | 11.2 % |
| **Logistic regression (chosen)** | 0.878 [0.840, 0.910] | 0.705 [0.587, 0.793] | 0.1013 | 0.621 | 39.7 % |
| MLP | 0.881 [0.844, 0.913] | 0.707 [0.596, 0.792] | 0.1012 | 0.616 | 40.6 % |
| LSTM | 0.880 [0.842, 0.912] | 0.714 [0.602, 0.798] | 0.1001 | 0.630 | 41.1 % |

- Paired bootstrap differences between the learned models all include 0 → **statistical tie**.
- Chosen model at threshold 0.306: recall 69 %, precision 56 %, 25 % of students flagged
  (TP 155, FP 120, FN 69, TN 756). Accuracy 82.8 % is not informative: predicting "fine" for
  everyone scores 79.6 %.
- Bands: Low / Moderate / High hold 812 / 157 / 131 rows with observed difficulty
  8.3 % / 36.3 % / 76.3 % — each within its score range.
- Validation ROC-AUC was higher (0.926); 7-fold student-grouped cross-validation (0.896–0.934)
  shows the gap is ordinary sampling variation (`reports/split_variation.md`).

Figures: `reports/figures/{roc,pr,calibration,confusion,risk_bands}_test.png`; the dashboard's
Model evaluation page draws the same curves from `reports/evaluation_curves.json`.

## 6. Discussion

**Why does the LSTM not win?** In this synthetic data the next semester depends mainly on the
student's current level, which the latest semester already shows. A diagnostic
(`reports/signal_diagnostic.md`) found that history summaries add nothing and that even an
oracle given the hidden generating variables reaches only ROC-AUC 0.936 — the remaining
uncertainty is noise by construction. When history carries no extra information, a sequence
model cannot outperform a snapshot model. On real data with richer within-student dynamics,
the LSTM might help; that is untested.

**Attendance "explaining away".** Among students with the same grades, those with lower
attendance were estimated as slightly *less* at risk, because in the generator engagement
raises both attendance and marks. The dashboard shows this honestly with a note, and the
attendance suggestion follows the college's 75 % guideline rather than the model
(`reports/explanations.md`).

## 7. System

FastAPI back end (`src/scholartrack/api/`) with health, model information, metrics, demo,
analytics, single and batch prediction endpoints; strict upload limits; a consistent error
format; counts-only logging; optional history that stores no identifiers (off by default).
React + TypeScript + Tailwind + Recharts dashboard with six pages: Overview, Student risk,
Batch prediction (CSV validation, preview without names, sortable results, CSV download),
Analytics (groups < 10 suppressed), Model evaluation and About. Architecture:
`docs/ARCHITECTURE.md`.

## 8. Testing and quality

- 162 Python tests (data validation, adapter, targets, generator reproducibility, feature
  no-look-ahead, split leakage, models, evaluation, explanations, API, repository hygiene);
  4 skip when the private reference CSV is absent (as in CI).
- 10 frontend tests (formatting, CSV export, preview hides names, sorting, page rendering).
- ruff lint and format, TypeScript strict type-check, ESLint.
- GitHub Actions runs all of the above, an API smoke test, and builds the Docker image and
  checks its health endpoint. First run on GitHub: all three jobs green.

## 9. Ethics, privacy and limitations

- Decision support only; scores must not be used to penalise, exclude or label students.
- No student-level data in the public repository (enforced by tests). Names and PRNs are never
  model inputs; uploads are processed in memory; analytics suppress small groups.
- No authentication exists, so the public demo must use synthetic data only.
- All metrics describe a synthetic process. Real use needs local data with observed outcomes,
  re-validation, a fairness review across groups, and institutional approval.
- Target thresholds are illustrative until the college confirms its rules.

## 10. Conclusion and future work

The pipeline from raw college CSV to calibrated, explained risk scores works end to end and
is reproducible. On the synthetic data, logistic regression, an MLP and an LSTM perform
equally well, so the simplest model is the sensible default. Next steps: obtain real
multi-semester records with outcomes under an approved data agreement; add the UCI 697
benchmark once its host is reachable; confirm thresholds with the college; run a fairness
analysis; and add institutional authentication before any real deployment.

   the band bars.

   scores, contributing factors with the explanation note, suggestions, semester history.
3. **Batch prediction**: upload a college-format CSV (e.g. a file from
   `data/synthetic/college_format/`) → preview (names hidden), validation report, predictions,
   sort, open a row, **Download CSV**.
4. **Analytics**: change cohort and semester filters; mention small-group suppression.
5. **Model evaluation**: table with confidence intervals, ROC / PR / calibration curves,
   confusion matrix, Top-K capture, band check.
6. **About**: limitations and responsible use.
7. Optional: `/api/docs` (interactive API) and the GitHub Actions run.
